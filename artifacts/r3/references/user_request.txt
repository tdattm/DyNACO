## 5. STAGE A — INDEPENDENT 2-OPT DIAGNOSTIC

Stage A must preserve original solver behavior.

Prefer a standalone C++ diagnostic module invoked from Python instead of changing the production C++ solver.

Implement an independent tour/move checker.

### 5.1 Correct 2-opt reference

Given a valid cyclic TSP tour, enumerate all distinct valid pairs of nonadjacent tour edges.

Exclude:

- Identical edges
- Adjacent edges
- Wraparound-adjacent edges
- Invalid endpoint combinations
- Moves that do not form a single valid Hamiltonian cycle

For removed edges `(a,b)` and `(c,d)`, evaluate:

`gain = dist(a,b) + dist(c,d) - dist(a,c) - dist(b,d)`

Match the solver's exact tour distance convention, but compute an independent float64 reference.

Do not use rounded TSPLIB EUC_2D edge costs for synthetic Euclidean instances unless the original solver does so.

Use coordinate values actually provided to the native solver.

Validate gain by applying selected moves to copied tours, recomputing total length independently, and comparing observed decrease with calculated gain.

Include deliberately constructed small examples with known optimal moves, no improving moves, collinear points, duplicated/near-duplicated coordinates, and numerically marginal moves.

A move is considered a robust improvement only if:

`gain > max(1e-8, 1e-6 * current_tour_length)`

Also preserve the raw signed gain before thresholding.

Do not silently classify near-zero numerical improvements as genuine improvements.

### 5.2 Candidate graph coverage

On the same frozen tour, construct or load:

- Original K32 candidates
- K40 candidates
- K48 candidates
- K64 candidates
- Full 2-opt reference

Validate candidate identities and ranking against the native backend.

If an independently constructed list differs, investigate and report the discrepancy. Use the native K32 list as authoritative for baseline-matching diagnostic.

Define candidate eligibility using the actual source-code semantics, including candidate direction, both scan orientations, and edge ordering.

Deduplicate 2-opt moves by canonical tour-edge pair.

Do not incorrectly count the same move multiple times merely because multiple anchors can generate it.

For each snapshot, calculate:

- Number of valid full 2-opt moves
- Number of improving full 2-opt moves
- K32-eligible improving moves
- K40-eligible improving moves
- K48-eligible improving moves
- K64-eligible improving moves
- Newly covered moves for each K increment
- Missed move count
- Missed count rate
- Gain-weighted coverage
- Largest missed gain
- Gain distribution of missed moves
- Node-level missed gain concentration
- Distances/ranks of newly useful candidate edges

Always distinguish the candidate-membership-only definition from the exact `two_opt_nn` scanning/pruning definition.

### 5.3 SRR versus graph limitation

Implement independent classification for:

- Candidate edge unavailable
- Candidate edge available but no eligible checklist anchor
- Candidate available but pruned
- Candidate available and potentially evaluated
- Candidate available and evaluated but not selected
- Move actually accepted by the native SRR

A move may have more than one representation or anchor.

Preserve independent boolean eligibility fields; do not rely solely on mutually exclusive labels.

Use all-node checklist analysis as a scope-independent reference.

Attempt to reconstruct the actual checklist and perturbation trajectory using native traces and pre-SRR tours.

The reconstruction must model the actual relocation order and source-tour edge semantics.

Verify reconstructed raw tours exactly against native raw tours before trusting reconstructed checklist membership.

If checklist reconstruction fails, mark exact checklist coverage unavailable.

Do not invent or infer an actual checklist from an empty `touched_list`.

If genuinely required, consider a small, disabled-by-default, passive instrumentation hook only after documenting why existing interfaces are insufficient.

Any native instrumentation must have regression tests showing no change to route selection, RNG behavior, objective values, pheromone, and solver state when the hook is disabled.

Do not treat a full all-node scan as equivalent to the real scope-restricted solver.

### 5.4 Gain recovery on copied tours

For selected missed moves:

1. Copy the frozen tour.
2. Apply the proposed 2-opt reversal.
3. Revalidate permutation and cyclic tour structure.
4. Recompute length in float64.
5. Verify realized one-step improvement.
6. Record the additional cost of evaluating/applying the move.

This is an oracle feasibility diagnostic.

Never describe a one-step oracle improvement as a gain actually achieved by DyNACO.

Do not sum independent single-move gains and present the sum as achievable tour improvement.

If running a sequential independent 2-opt repair, explicitly label it as an alternative postprocessor with a changed move budget, not as unchanged DyNACO.

### 5.5 Efficiency

Implement the full 2-opt scan in C++17 or equivalent compiled code.

The reference loop should use O(N²) time without requiring O(N²) persistent memory.

Use streaming aggregations, histograms, bounded top-gain storage, and small sampled detailed records.

Do not materialize all pairwise moves for TSP-5K or larger.

Avoid per-pair Python calls.

Record time separately for:

- State extraction
- KNN verification/construction

## 7. PREDECLARED SELECTIVE EXPANSION SCREEN

The purpose is to test whether nonuniform allocation has potential before implementing a modified solver.

Use the same frozen tour and candidate universe for every comparison.

Base graph: K32.

Candidate pool: neighbors ranked 33 through 64, following the verified native neighbor-ranking convention.

Additional directed-edge budget:

`B = 8 * N`

For TSP-1K, this is 8,000 additional directed candidate slots.

Keep distinct directed slots separate from unique undirected-edge counts.

Report both quantities.

Compare the following offline graph policies:

### A. Uniform K40

Every node receives eight additional nearest candidates, ranks 33–40.

Total extra directed slots: `8N`.

### B. Random concentrated expansion

Randomly choose 25% of nodes.

Each chosen node receives 32 extra nearest candidates, ranks 33–64.

Use 10 independently seeded random allocations per frozen snapshot, without altering baseline RNG state.

Total extra directed slots: `8N`.

Report both individual random results and the mean random-control performance.

### C. Predefined geometry/tour-excess selector

For each node `u`, calculate:

`score(u) = max(d(u,pred(u)), d(u,succ(u))) / mean_distance_to_K32_neighbors(u)`

Use a stable epsilon to avoid division by zero.

Select the 25% of nodes with the largest scores, with deterministic node-index tie-breaking.

Allocate 32 extra nearest candidates to each selected node, ranks 33–64.

Total extra directed slots: `8N`.

This selector is deterministic and does not use oracle 2-opt gain.

Do not alter its scoring rule after inspecting principal results.

### D. Full K64 reference

All nodes receive 32 extra candidates.

Total extra directed slots: `32N`.

This is a higher-budget upper comparison, not an equal-budget control.

### E. Oracle diagnostic only

Optionally calculate the best allocation using observed improving-move gains under a fixed budget, solely to characterize headroom.

An oracle-derived selection is not a deployable heuristic.

It must not be used to make the heuristic selector pass the GO gate.

### Offline selector metrics

Evaluate all-node, candidate/pruning-aware improving-move coverage on exactly the same frozen tours.

Measure:

- Incremental improving moves covered beyond K32
- Incremental gain mass beyond K32
- Gain-weighted coverage
- Maximum newly recoverable one-step gain
- Per-node edge allocation
- Directed slot budget
- Unique undirected edge counts
- Duplicate/self-loop/invalid-edge checks
- Diagnostic calculation time

The comparison must not imply a realized solver improvement.

- Uniform K40
- Mean random concentrated expansion

on at least 6 of the 8 independent instances.

The median instance-level improvement ratio must also be at least 1.10 against each comparator.
